# همدل — سامانه‌ی گفت‌وگو و کلاس دبیرستان شاهد شهیدان فهیمی

سامانه‌ی گفت‌وگو، آزمون آنلاین، تکالیف، حضور و غیاب و اطلاعیه‌های مدرسه.
داده‌ها در **PostgreSQL (Supabase)** و تصاویر در **Supabase Storage** ذخیره می‌شوند و همه‌ی کاربران روی یک داده‌ی مشترک کار می‌کنند.

## فناوری

- Next.js 16 (App Router) و React 19
- PostgreSQL از طریق `pg` (Supabase)
- Supabase Storage برای تصاویر
- Tailwind CSS و lucide-react

## راه‌اندازی محلی

```bash
npm install
cp .env.example .env.local   # و مقادیر واقعی را وارد کنید (این فایل در Git نیست)
npm run dev
```

## متغیرهای محیطی

| نام | توضیح |
|---|---|
| `DATABASE_URL` | رشته‌ی اتصال PostgreSQL (الزامی) |
| `SUPABASE_URL` | آدرس پروژه‌ی Supabase (برای تصاویر) |
| `SUPABASE_SERVICE_ROLE_KEY` | کلید سرویس Supabase؛ فقط سمت سرور (برای تصاویر) |
| `SUPABASE_STORAGE_BUCKET` | نام سطل تصاویر؛ پیش‌فرض `hamdel-media` |
| `HAMDEL_STAFF_KEY_HASH` / `HAMDEL_DEV_LOGIN_HASH` / `HAMDEL_WIPE_HASH` | اختیاری: هش SHA-256 کدهای محرمانه |

کلیدها و رمزهای واقعی هیچ‌وقت در کد یا Git قرار نمی‌گیرند؛ در کد فقط هش SHA-256 کدهای محرمانه (برای مقایسه) وجود دارد. فایل `.env.example` فقط جای‌نگهدار دارد.

## ساخت پایگاه‌داده

جدول‌ها هنگام اولین درخواست به‌صورت خودکار ساخته می‌شوند (`src/db/schema.ts`، idempotent). سطل `hamdel-media` هم در صورت نبودن ساخته می‌شود، به شرط داشتن کلید سرویس.

وضعیت سلامت: `GET /api/health` → `{ "ok": true, "database": "postgres", ... }`

## اولین مدیر سامانه

سایت با داده‌ی صفر شروع می‌شود و هیچ حساب پیش‌فرضی ندارد.

1. با **ورود مدیر ارشد** (کد و شماره‌ی آن نزد مدیر فنی مدرسه است) وارد شوید.
2. از **پنل مدیریت ← افزودن عضو کادر**، یک حساب با سمت **مدیر** بسازید.
3. با همان حساب وارد شوید و بقیه‌ی کادر و دانش‌آموزان را ثبت کنید.

ثبت‌نام خودِ کادر از صفحه‌ی ورود فقط با **کد ثبت‌نام کادر** انجام می‌شود که مدیر فنی در اختیار دارد. دانش‌آموزان خودشان ثبت‌نام می‌کنند.

## امنیت داده

- کاربران فقط داده‌های مجاز برای نقش خود را از سرور دریافت می‌کنند (فیلدهای خصوصی دیگران مثل شماره، کد ملی و رمز پنهان است؛ دانش‌آموز فقط گفتگوهایی را می‌بیند که عضوش است).
- هر تغییر پیش از ذخیره روی سرور اعتبارسنجی و بررسی دسترسی می‌شود.
- نشست‌ها با توکن تصادفی ساخته می‌شوند و در پایگاه‌داده فقط هش آن‌ها ذخیره می‌شود.
- پاک‌سازی کامل داده‌ها فقط برای مدیریت و با رمز جداگانه ممکن است.

محدودیت شناخته‌شده: رمز عبور کاربران در همان ساختار نسخه‌ی اصلی به‌صورت متن ساده ذخیره می‌شود. برای مدرسه‌ی واقعی توصیه می‌شود هش‌سازی رمز و بازنشانی آن اضافه شود.

## آزمون

```bash
npm run test:e2e
```

این دستور پایگاه‌داده‌ی آزمایشی PGlite را بالا می‌آورد، برنامه را می‌سازد و اجرا می‌کند و سپس:

- آزمون API (۲۸ مورد): سلامت، شروع با داده‌ی صفر، ورود و ثبت‌نام، دسترسی‌ها، آپلود، پاک‌سازی.
- آزمون همگام‌سازی کلاینت (۱۸ مورد): ذخیره‌ی تغییرات، ارسال دسته‌ای، دریافت تغییرات دیگران، برگشت تغییر ممنوع، پاک‌سازی.

دستورهای کامل: `npm run typecheck`، `npm run lint`، `npm run build`.

## استقرار روی Vercel

1. پروژه را به مخزن GitHub وصل کنید.
2. متغیرهای `DATABASE_URL`، `SUPABASE_URL`، `SUPABASE_SERVICE_ROLE_KEY` و `SUPABASE_STORAGE_BUCKET` را به‌صورت Encrypted تعریف کنید.
3. Deploy کنید؛ سپس `/api/health` را بررسی کنید.

## ساختار

- `src/app/api/*`: مسیرهای سرور (ورود، ثبت‌نام، همگام‌سازی، تغییرات، آپلود، پاک‌سازی، سلامت)
- `src/db/`: اتصال و طرح پایگاه‌داده
- `src/lib/server/`: نشست، دسترسی، رکوردها، Storage
- `src/lib/store.ts`: کش همگام با سرور در مرورگر
- `src/lib/model.ts`: منطق دامنه و API عمومی `DB.*`
- `src/components/`: رابط کاربری
- `scripts/e2e/`: آزمون‌های یکپارچه
