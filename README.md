# هَمدِل — سامانه‌ی یکپارچه‌ی مدرسه

سامانه‌ی کامل مدیریت مدرسه برای **دبیرستان شاهد شهیدان فهیمی**: اطلاعیه، گفت‌وگو، تکلیف، آزمون آنلاین، حضور و غیاب، پروفایل و مدیریت کاربران — با رابط کاربری فارسی و راست‌به‌چپ، ساخته‌شده با **Next.js 16**، React، Tailwind CSS، **Drizzle ORM** و **PostgreSQL** (Supabase).

> این نسخه **بدون هیچ داده‌ی نمونه** راه‌اندازی می‌شود. تنها حساب و رمزهای پیش‌فرض، مدیر و رمز حذف است؛ بقیه‌ی اطلاعات (کاربران، کلاس‌ها، درس‌ها، پیام‌ها، تصاویر و …) را مدیر از داخل سامانه ثبت می‌کند و همه‌ی آن‌ها در Supabase ذخیره می‌شوند.

## ✨ امکانات

| بخش | توضیح |
| --- | --- |
| **داشبورد** | نمای اختصاصی برای مدیر، دبیر و دانش‌آموز؛ آمار، تکالیف باقی‌مانده، صف تصحیح و اطلاعیه‌های اخیر |
| **اطلاعیه‌ها** | انتشار برای همه، دانش‌آموزان، دبیران یا یک کلاس؛ تصویر پیوست، سنجاق‌کردن و انقضا |
| **گفت‌وگو** | گفت‌وگوی کلاسی، پیام مستقیم (در صورت فعال‌بودن در تنظیمات)، ارسال تصویر و خوانده‌شدن پیام‌ها |
| **تکالیف** | ساخت تکلیف با مهلت، بارم و تصویر پیوست؛ ارسال پاسخ، نمره‌دهی و بازخورد |
| **آزمون آنلاین** | آزمون با زمان‌بندی و تصویر سؤال، تصحیح خودکار، کارنامه و رتبه‌بندی با آواتار |
| **حضور و غیاب** | ثبت حضور هر زنگ (۱ تا ۸)، آواتار دانش‌آموزان، و پاک‌کردن جلسه‌ی ثبت‌شده با رمز حذف |
| **پروفایل** | آپلود و تغییر عکس پروفایل، بیوگرافی و رمز عبور شخصی |
| **مدیریت** | کاربران و ثبت‌نام در کلاس، کلاس‌ها و سال تحصیلی، سر کلاس (Homeroom)، درس‌ها، تخصیص دبیر–کلاس–درس، تنظیمات مدرسه، تغییر رمز حذف، پاک‌سازی انتخابی و لاگ ممیزی |

همه‌ی حذف‌های حساس (پیام‌ها، اطلاعیه‌ها، تکالیف، آزمون‌ها، حضور، پاک‌سازی و حذف کاربر) با **مودال رمز حذف** انجام می‌شود.

## 🔑 ورود اولیه

| نقش | نام کاربری | رمز عبور |
| --- | --- | --- |
| مدیر مدرسه | `admin` | `admin1234` |
| رمز حذف (پیش‌فرض) | — | `delete1234` |

> **مهم:** پس از اولین ورود، رمز مدیر را از بخش «پروفایل» و رمز حذف را از بخش «مدیریت ← تنظیمات و امنیت» تغییر دهید. این مقادیر فقط برای راه‌اندازی اولیه‌اند.

هیچ دکمه‌ی ورود نمایشی یا راهنمای رمز نمونه در صفحه‌ی ورود وجود ندارد.

### ترتیب پیشنهادی راه‌اندازی مدرسه

1. ورود با حساب مدیر و تغییر رمزها.
2. «مدیریت ← تنظیمات» و تنظیم نام مدرسه و سال تحصیلی.
3. «مدیریت ← درس‌ها» و ثبت دروس.
4. «مدیریت ← کلاس‌ها» و ساخت کلاس‌ها (نام، پایه، رشته، اتاق، سال تحصیلی) و تعیین سر کلاس (Homeroom).
5. «مدیریت ← کاربران» و ساخت حساب دبیران و دانش‌آموزان؛ برای دانش‌آموز می‌توانید کلاس را هم همان‌جا انتخاب کنید.
6. «مدیریت ← کلاس‌ها ← ثبت‌نام» برای افزودن یا حذف دانش‌آموزان یک کلاس به‌صورت گروهی.
7. «مدیریت ← برنامه‌ی تدریس» برای وصل‌کردن دبیر، کلاس و درس.

## 🗄️ پایگاه‌داده و ذخیره‌سازی (Supabase)

- **جدول‌ها:** ۱۹ جدول (کاربران، جلسات ورود، کلاس‌ها، ثبت‌نام، درس‌ها، تخصیص‌ها، تکالیف، پاسخ‌ها، آزمون‌ها، سؤال‌ها، پاسخ‌ها، پیام‌ها، اطلاعیه‌ها، حضور، لاگ ممیزی، فایل‌های رسانه، تنظیمات). مدل داده در `src/db/schema.ts` است.
- **مهاجرت‌ها:** در `src/db/migrations.ts` جاسازی شده‌اند و در اولین اجرا به‌ترتیب اعمال می‌شوند (جدول `__migrations` ردیف‌های اعمال‌شده را نگه می‌دارد).
- **RLS:** روی همه‌ی جدول‌ها فعال است و هیچ سیاستی برای `anon`/`authenticated` تعریف نشده است؛ یعنی فقط سرور (با اتصال مستقیم PostgreSQL) به داده‌ها دسترسی دارد.
- **Storage:** سطل عمومی `hamdel-media` برای عکس پروفایل، تصاویر پیام‌ها، اطلاعیه‌ها، تکالیف، پاسخ‌ها و آزمون‌ها. محدودیت: فقط JPEG/PNG/WebP/GIF و حداکثر ۴ مگابایت برای هر فایل.
- **تصویر حذف‌شده:** هنگام حذف پیام/اطلاعیه/آزمون و پاک‌سازی، فایل‌های مرتبط هم از Storage پاک می‌شوند.

### راه‌اندازی یک پروژه‌ی جدید Supabase

1. پروژه‌ی جدید بسازید (منطقه‌ی پیشنهادی `eu-central-1`).
2. از **Project Settings → Database** رشته‌ی اتصال Session pooler (پورت 5432) را بگیرید و به‌صورت `DATABASE_URL` تنظیم کنید؛ یا `SUPABASE_PROJECT_REF`، `SUPABASE_DB_PASSWORD` و `SUPABASE_REGION` را بدهید.
3. از **Project Settings → API** مقادیر `Project URL` و `service_role` را در `SUPABASE_URL`، `NEXT_PUBLIC_SUPABASE_URL` و `SUPABASE_SERVICE_ROLE_KEY` قرار دهید.
4. اولین اجرای برنامه جدول‌ها، سطل Storage و حساب مدیر را خودکار می‌سازد. نیازی به درج داده‌ی نمونه نیست.

کلیدهای واقعی هرگز در مخزن Git قرار نمی‌گیرند؛ فقط در `.env.local` (محلی) یا Environment Variables پروژه‌ی Vercel.

## 🚀 اجرای محلی

```bash
npm ci
cp .env.example .env.local   # و مقادیر را پر کنید
npm run dev
```

آدرس <http://localhost:3000> را باز کنید.

- بدون تنظیم `DATABASE_URL` یا مشخصات Supabase، برنامه برای تست محلی از **PGlite** (PostgreSQL در قالب WebAssembly) در مسیر `./.data/pglite` استفاده می‌کند.
- برای شروع از صفر محلی: `npm run db:reset` را اجرا کنید.

### اسکریپت‌ها

| دستور | کاربرد |
| --- | --- |
| `npm run dev` | اجرای توسعه |
| `npm run build` / `npm start` | ساخت و اجرای نسخه‌ی تولیدی |
| `npm run typecheck` | بررسی تایپ‌ها |
| `npm run lint` | بررسی ESLint |
| `npm run db:generate` | تولید مهاجرت جدید از `schema.ts` (drizzle-kit) |
| `npm run db:embed` | جاسازی مهاجرت‌ها در `src/db/migrations.ts` |
| `npm run db:check` | شمارش ردیف‌ها و بررسی اتصال پایگاه‌داده |
| `npm run db:reset` | پاک‌کردن پایگاه‌داده‌ی محلی PGlite |

## ☁️ استقرار در Vercel

1. پروژه را به مخزن GitHub وصل کنید (Framework: Next.js، Build: پیش‌فرض).
2. متغیرهای محیطی `.env.example` را (بدون مقادیر نمونه) در **Environment Variables** تعریف کنید. حداقل: `DATABASE_URL` (یا مشخصات Supabase) و `SUPABASE_URL` / `NEXT_PUBLIC_SUPABASE_URL` / `SUPABASE_SERVICE_ROLE_KEY`.
3. دیپلوی کنید. روی Vercel اگر `DATABASE_URL` تنظیم نشده باشد، برنامه عمداً خطا می‌دهد تا داده‌ها روی فایل‌سیستم موقتی از دست نروند.
